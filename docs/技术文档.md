## 1. 项目概述

### 1.1 定位

SpeakPal 是一个**场景化的 AI 英语口语诊断陪练**：学习者注册登录后，选择一个真实场景（求职面试 / 咖啡店点单 / 雅思 Part 1 / 酒店入住 / 机场值机 / 餐厅点餐），与 AI 角色进行多轮**语音**对话；对话结束后，系统给出综合分、维度分（3/4/5 维随作答方式变）、逐句"更地道说法"的纠错报告，以及与本次对话相关的流利度客观指标。

与同类"陪聊"产品的差异点在于**可验证**：系统的评分结论不是自说自话，而是配有 `evaluation/` 验证层，用 ICC、kappa、Bland-Altman、MAE/RMSE 等统计量与人评金标准对齐，且脚本可复现。

### 1.2 核心能力

| 能力 | 实现方式 | 入口 |
|---|---|---|
| 注册 / 登录 | 用户名密码 + PBKDF2-SHA256 散列 + JWT | `POST /api/auth/register`、`POST /api/auth/login` |
| 场景选择 | 后端内置 6 个场景定义 | `GET /api/scenes` |
| 多轮对话 | 大模型按角色设定推进，保留最近 8 条消息（约 4 轮问答）上下文 | `POST /api/sessions/{id}/turn` |
| 语音输入 | 浏览器 Web Speech API 转写 | 前端 `src/utils/speech.ts` |
| AI 朗读 | `speechSynthesis` | 同上 |
| 发音/流利度客观指标 | Web Audio 包络分析 + 文本特征提取 | `src/utils/audio.ts`、`evaluation/features.py` |
| 评分报告 | 大模型按 rubric 输出 JSON，落库 | `POST /api/sessions/{id}/finish` |
| 逐句纠错 | 报告中的 `sentence_fixes` | `GET /api/sessions/{id}/report` |
| 历史记录 | 按 `user_id` 隔离 | `GET /api/sessions` |
| 服务端语音转写 | 录音转 16 kHz 单声道 WAV 上传，DeepSeek `/tools/asr` 或 OpenAI 兼容 `/audio/transcriptions`；失败返回 `source=none`，前端回退浏览器识别 | `POST /api/asr` |
| 拍照生成练习 | 图片 → 场景 / 场景细节 / 目标词 / 开场白（官方主机强制 `deepseek-flash` Vision） | `POST /api/scenes/from-image` |
| 知识检索（RAG） | `bm25s` 检索 60 语法卡 + 60 口语卡 + 600 词；评分时注入最多 8 张，纠错用 `rule_ref` 回链 | `services/rag.py`、`GET /api/knowledge/search` |
| Agent 诊断教练 | 函数调用最多 4 步、每步 ≤3 次工具；证据校验后写 `reports.coach_json` | `services/agent.py`、`services/tools.py` |
| AI 安全 | 输入注入只标记不拦截；输出不合格换预设追问；图片只做类型/大小校验 | `services/safety.py` |
| MCP 服务 | 8 工具 2 资源，stdio 与 streamable-http 两种传输 | `backend/mcp_server.py` |
| AI 透明度 | 报告返回模型名、安全标记计数、模型/规则分占比、教练证据覆盖 | `ReportOut.transparency` |
| 运营后台 | 单页 HTML + 管理密钥 | `GET /`、`GET /admin` |
| 评分可验证 | 纯标准库统计工具 + CLI；另有 RAG 离线评测 | `python -m evaluation.validate`、`python -m evaluation.rag_eval` |

### 1.3 非目标与边界

以下内容**不在**当前实现范围内，文档中相关表述不得被理解为已具备：

- 不是专业声学测评：发音维度由大模型**依据转写文本推断**；正常报告注脚是「分数由模型分与可测规则分融合得出，仅供参考」，只有降级报告才写「示例报告 · 本次不计分」。
- 不做音频存储：服务端 ASR 只在内存里转发一段 WAV（处理完立即丢弃），不写文件、不落库；库内只保存录音的**统计元信息**（时长、停顿），原始录音只在浏览器本地。
- 识图只承诺官方主机 `deepseek-flash` 支持 Vision：第三方兼容端点不保证；模型不支持图片时前端提示换模型，不静默失败。
- 无真实人工评分数据：`evaluation/demo_data.csv` 是固定随机种子生成的合成数据，仅用于验证脚本可跑通，不构成任何有效性结论。
- 无多租户/班级/作业体系，无教师端；管理台只做只读统计。
- 有自动化测试：`backend/tests/` 下 `test_api.py` + `test_scales.py`，当前 269 条用例全绿（见 11.3）。

## 2. 术语与缩写

| 术语 | 含义 |
|---|---|
| Session（练习会话） | 一次从选择场景到生成报告的完整练习，对应 `sessions` 表一行 |
| Turn（轮次） | 会话中的一条消息，`role` 为 `ai` 或 `user`，对应 `turns` 表一行 |
| Report（报告） | 会话结束后生成的评分结果，与 Session 一对一，对应 `reports` 表一行 |
| rubric | 评分量表；本系统按维度给雅思 band 并换算 0–100 分，维度数随作答方式变（3/4/5 维） |
| ICC | 组内相关系数（Intraclass Correlation Coefficient），衡量评分者一致性 |
| kappa | 类别型一致性系数，本系统用于 A/B/C 档位 |
| Bland-Altman | 两种测量方法一致性的偏差分析（均值差 + 95% 一致性界限 LoA） |
| MTLD | 词汇多样性指标（Measure of Textual Lexical Diversity），此处为近似实现 |
| TTR | Type-Token Ratio，类符/形符比 |
| mock | 未配置大模型密钥时的内置假数据回复，保证流程可跑通 |

### 3.3 技术选型与理由

| 层 | 选型 | 版本约束 | 选择理由 |
|---|---|---|---|
| 前端框架 | Vue 3 + `<script setup>` | `^3.5.0` | 组合式 API 代码量小，单文件组件适合小团队 |
| 构建 | Vite | `^5.4.0` | 冷启动快，内置代理，零配置支持 Vue |
| 样式 | Tailwind CSS | `^3.4.10` | 原子类，避免维护独立 CSS 文件；`style.css` 仅 3 行 `@tailwind` + body 基础样式 |
| 路由 | vue-router（history 模式） | `^4.4.0` | SPA 常规方案；除 Login/Home 外全部按页懒加载 |
| 状态 | Pinia（setup store 写法） | `^2.2.0` | 与 Vue3 组合式 API 一致 |
| 类型 | TypeScript + vue-tsc | `^5.9.3` / `^3.3.14` | 全量迁移到 `.ts`，`build` 先跑 `vue-tsc --noEmit` |
| Lint | ESLint 10 flat config + typescript-eslint + eslint-plugin-vue | `^10.15.0` / `^8.73.0` / `^10.12.1` | 只用 `flat/essential`，避免整仓模板重排 |
| HTTP | axios | `^1.7.0` | 拦截器便于统一注入 token、统一处理 401 |
| 后端框架 | FastAPI | `>=0.110`（实测 0.162.0） | Pydantic 校验 + 自动 OpenAPI，`/docs` 可直接当接口文档 |
| ORM | SQLAlchemy 2.x | `>=2.0`（实测 2.1.6） | 声明式模型，便于换库 |
| 数据库 | SQLite | 内置 | 零运维，校赛场景足够；通过 `DATABASE_URL` 可切换 |
| 鉴权 | PyJWT（HS256） | `>=2.8` | 无状态，前端存 localStorage 即可 |
| 大模型调用 | httpx + OpenAI 兼容 REST | `>=0.27` | 不绑定厂商 SDK，改 `LLM_BASE_URL` 即换供应商；默认 `deepseek-flash` |
| 检索 | bm25s | `>=0.3,<0.4`（实测 0.3.16） | 纯 Python 关键词检索，索引常驻内存，不下载模型、不落盘 |
| 文件上传 | python-multipart | `>=0.0.9`（实测 0.0.34） | FastAPI 接收 `/api/asr`、`/api/scenes/from-image` 的 multipart 必需 |
| MCP | mcp | `>=2.3,<3`（实测 2.3.0） | 标准 MCP server；2.x 把 `FastMCP` 改名为 `MCPServer` |
| 统计 | 纯标准库 `math` | — | 避免引入 numpy/scipy，保证"评审机器上开箱可跑" |

**关键取舍**：`evaluation/` 刻意不依赖第三方统计库。`agreement.py` 手写了方差分析（ANOVA）来算 ICC，代价是代码需要自行校验，收益是在任何 Python 3 环境下都能复现结果——这正是"可验证"命题成立的前提。

### 3.4 代码分层与依赖方向

```
routers/ ──► services/ ──► config
   │            │  ├─ llm（唯一模型出口）→ agent / scoring / scenes / asr
   │            │  ├─ rag ──► library / wordbank
   │            │  └─ safety / rules / srs …
   ├──► models/ ──► db ──► config
   ├──► schemas（Pydantic DTO）
   ├──► security ──► models, db, config
   └──► evaluation.features / bands / scales（跨包复用，见 4.8）

mcp_server.py（独立进程）──HTTP──► routers/（用户令牌鉴权）
```

约定：

- `routers/` 只做参数校验、权限判断、编排，不写业务规则。
- `services/` 不接触 `Request`/`Response`，只接收纯 Python 结构（`dict`、`list`），因此可单独测试与复用。
- **所有模型调用都收口到 `services/llm.py`**：`chat()` / `chat_json()` 是唯一出口，全仓直接拼 `/chat/completions` 的地方只剩 3 处（`llm.chat`、`llm.open_chat_stream`、`system.py` 的密钥连通性测试）。
- `schemas.py` 是所有对外 JSON 形状的唯一定义处，`ReportOut`、`TurnOut` 等均由它约束。

## 4. 后端设计

### 4.1 应用入口与中间件

`backend/app/main.py` 是唯一入口，职责如下：

| 顺序 | 代码 | 作用 |
|---|---|---|
| 1 | `Base.metadata.create_all(bind=engine)` | 启动时建表（幂等） |
| 2 | `_ensure_schema()` | 轻量"迁移"：缺列则 `ALTER TABLE` 补齐 |
| 3 | `FastAPI(..., docs_url=None, redoc_url=None)` | 关闭内置文档，改用本地 Swagger 资源 |
| 4 | `app.mount("/static", StaticFiles(...))` | 提供 `admin.html` 与 Swagger bundle |
| 5 | `CORSMiddleware` | 全开跨域 |
| 6 | `include_router(...)` × 14 | 注册 admin / auth / scenes / sessions / reports / account / system / exercises / hints / tts / study / words / knowledge / asr |
| 7 | `GET /docs` | 自定义 Swagger UI（引用本地 JS/CSS，离线可用） |
| 8 | `GET /`、`GET /admin` | 直接返回 `static/admin.html` 文本 |
| 9 | `GET /api/health` | 健康检查 `{"status": "ok"}` |

**Schema 演进机制**：项目未引入 Alembic。`_ensure_schema()` 通过 `inspect(engine)` 检查列是否存在，按需 `ALTER TABLE ... ADD COLUMN` 补齐；缺表则直接 `CREATE TABLE`（`hint_cache`、`review_events`、`note_links`、`note_link_mutes` 等）。适用于"只加列/只加表"的向后兼容变更；删除列、改类型、加约束需手工处理。阶段 0–5 新增的三列都走这条路径：`turns.asr_source`、`turns.safety_flag`、`reports.coach_json`。

> 实测确认：现有 `backend/speakpal.db` 已含 `features_json`、`audio_json`、`plan_json`、`coach_json`、`asr_source`、`safety_flag` 等列，迁移逻辑已在真实库上执行过。

### 4.2 配置

`backend/app/config.py` 用 `python-dotenv` 在导入时加载 `backend/.env`（相对当前工作目录，因此**必须从 `backend/` 目录启动**，启动脚本已保证这点）。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `JWT_SECRET` | 首次启动自动生成 48 字节随机串 | 弱值（空 / 公开默认串）会自动轮换并写回 `.env` |
| `JWT_ALGORITHM` | `HS256`（代码内固定） | 不可通过环境变量修改 |
| `JWT_EXPIRE_MINUTES` | `10080`（7 天） | token 有效期 |
| `DATABASE_URL` | `sqlite:///./speakpal.db` | 相对 `backend/` 解析；优先级：真实进程环境变量 > `data_location.json` > `.env` > 默认值 |
| `LLM_API_KEY` | **已删除** | 服务端不再持有模型 key，key 由客户端随 `X-LLM-Key` 头传入 |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容端点 |
| `LLM_MODEL` | `deepseek-flash` | 默认模型；`thinking: disabled` 与 `safety_check` 只对官方主机 `api.deepseek.com` 追加 |
| `ASR_MODEL` | `whisper-1` | 仅用于非 DeepSeek 主机的 `/audio/transcriptions`；官方主机走 `/tools/asr`，不用这个值 |
| `ADMIN_KEY` | 首次启动自动生成 12 字节随机串 | 弱值 `admin123` 会被替换；生成时打印在后端启动控制台 |

`.env` 已在 `.gitignore` 中，不会入库；仓库只提供 `.env.example`。

### 4.4 数据模型

`backend/app/models.py` 共 10 张表。

```

                    │
```

### 4.5 鉴权与安全

`backend/app/security.py`：

| 能力 | 实现 | 细节 |
|---|---|---|
| 口令散列 | `hash_password` | 16 字节随机盐 + `pbkdf2_hmac("sha256", …, 120000)`，存为 `base64(salt)$base64(dk)` |
| 口令校验 | `verify_password` | 重新派生后 `hmac.compare_digest`，常量时间比较；任何异常返回 `False` |
| 签发 | `create_token` | payload = `{sub: str(user_id), iat, exp}` |
| 校验 | `get_current_user` | `HTTPBearer(auto_error=False)` 取头；`jwt.decode` 失败统一 401；再查库确认用户仍存在 |

**错误语义**（实测）：

| 场景 | 状态码 | `detail` |
|---|---|---|
| 无 `Authorization` 头 | 401 | 未登录 |
| token 无效/过期 | 401 | 登录已失效，请重新登录 |
| token 指向已删除用户 | 401 | 用户不存在 |
| 管理密钥错误 | 401 | 管理密钥错误 |

**安全现状与风险**（详见 [12](#12-已知限制与技术债)）：

- 弱密钥自动轮换：`JWT_SECRET` / `ADMIN_KEY` 为空或公开弱值（含 `admin123`）时，启动即生成随机值写回 `.env`。
- CORS 已收紧为 `settings.cors_origins` 白名单（默认 `127.0.0.1:5173` / `localhost:5173`），不再是 `*`。
- 管理密钥仍由前端存放在 `localStorage.admin_key`，且明文比较（校赛范围可接受，生产应换服务端会话）。
- SSRF：模型 / TTS / ASR 地址都先过 `services/outbound.py` 的 DNS + IP 校验，默认拒绝 loopback / private / link-local；`ALLOW_PRIVATE_LLM_HOSTS=1` 才放开本地 Ollama。
- 模型侧安全：输入注入只打 `turns.safety_flag` 标记、不拦截（学习者可能正在练「ignore the previous instructions」）；平台 400 `Content Exists Risk` 与 200 `refusal` 都抛 `SafetyBlocked`，回复换成预设追问并标 `replaced`。

#### 4.7.1 场景定义（`services/scenes.py`）

场景是硬编码的 Python 列表，共 6 个，每个含 `id/name/icon/desc/role/opening`：

| id | 名称 | 角色设定 `role` | 开场白 `opening` |
|---|---|---|---|
| `job_interview` | 求职面试 | a friendly technical interviewer… | Hi, thanks for coming in today. Could you tell me a bit about yourself? |
| `cafe_order` | 咖啡店点单 | a barista at a busy coffee shop | Hi there! What can I get for you today? |
| `ielts_part1` | 雅思 Part 1 | an IELTS speaking examiner | Let's talk about where you live. Do you live in a house or an apartment? |
| `hotel_checkin` | 酒店入住 | a hotel receptionist at the front desk | Good evening! Do you have a reservation with us? |
| `airport_checkin` | 机场值机 | an airline check-in agent at the airport | Good morning! May I see your passport and booking, please? |
| `restaurant_order` | 餐厅点餐 | a friendly waiter at a casual restaurant | Good evening! A table for how many? |

#### 4.7.2 对话服务（`services/llm.py`）

- **入口**：`chat_reply(scene, difficulty, history, turn_index) -> str`
- **无 key 不降级为 mock 对话**：没有可用 key 时 `POST /sessions`、`/turn` 直接返回 `409 llm_not_configured`，不会生成一段假对话。
- **真实调用**：System prompt 规定"一次只问一个问题、先回应再追问、**对话中不纠错**（纠错留到报告）"；history 只取最近 8 条；`temperature=0.7`；超时 30s。
- **异常处理**：任何异常（含 4xx/5xx、超时、解析失败）都**降级为预设追问**，不抛出；并打一行 `[llm] 对话降级为预设追问：HTTP 500 / <异常名>`（stdout），不再是完全静默。

```python
# 关键 prompt 约定
f"You are {scene['role']}. The user is an English learner practicing speaking.\n"
"Ask short, natural, conversational questions. Ask only one question at a time.\n"
"After the user answers, briefly acknowledge, then ask one relevant follow-up.\n"
"Do not correct grammar during the conversation; correction is handled later.\n"
```

"对话中不纠错"是重要的产品决策：口语练习的连续性优先于即时纠错，纠错统一放在报告里，避免打断表达。

#### 4.7.3 评分服务（`services/scoring.py`）

- **入口**：`generate_report(scene, difficulty, history) -> dict`
- **真实调用**：单条 user message 承载整个 prompt；`temperature=0.2`（求稳定）；超时 60s；用 `re.search(r"\{.*\}", text, re.S)` 从回复中抠出第一个 JSON 块，`json.loads`；失败即生成**示例报告**（`source=mock`，分数/档位为 `null`，不借规则分凑成绩）。
- **输出契约**（prompt 中强约束）：模型按 IELTS band 描述符给**每维 band**（0.5 步长、3.0–9.0），不直接给 0–100 分：

```json
{
  "bands": {"pronunciation": 3.0, "fluency": 3.0, "grammar_vocab": 3.0,
            "task_completion": 3.0, "written_expression": 3.0},
  "sentence_fixes": [{"original": "", "better": "", "reason": "",
                      "error_type": "spelling|grammar|stiffness|wordiness",
                      "natural": "", "word": "",
                      "related": {"synonyms": [], "antonyms": [], "similar": []}}],
  "comment": "",
  "note": ""
}
```

维度出现规则：`pronunciation` / `fluency` 只在有录音轮时要求，`written_expression` 只在有打字轮时要求；`grammar_vocab` / `task_completion` 恒给（`scoring.py:203-212`）。

- **语言约定**：`comment` 与每条 `reason` 用简体中文；`original`/`better` 保持英文。
- **发音免责**：prompt 明确 `pronunciation is an estimate based on the transcript; do not claim precise acoustic analysis`。
- **模型分与规则分融合**：band 先按 `S = 10B + 10` 换 0–100，再与流利度 / 语言范围 / 任务清单规则分加权融合；模型分高出规则分 20 分以上压回规则分 +10（只压不抬，`rules.py:296-327`）。
- **降级基线**：模型不可用不再给假分数——`source=mock`、`total_score` / `band` / `cefr` 全为 `null`，`sentence_fixes` 只列用户真实说过的句子，注脚「示例报告（模型不可用） · 本次不计分」。

> 静默降级已修：`reports.source` 区分 `llm` / `mock`，`mock_reason` 落库（`not_configured` / `unavailable` / `invalid_key`），降级时 `print` 一行 `[scoring] 降级为示例报告（…）`（`scoring.py:162`）。

#### 4.7.4 轮次与报告编排（`routers/sessions.py`）

`add_turn` 的完整流程：

1. 查会话并校验归属 → 404；状态非 `active` → 400「会话已结束」。
2. 若带 `audio`，序列化为 JSON 写入 `turns.audio_json`；`asr_source`（`cloud` / `browser`）随 user turn 落库。
3. 输入过 `safety.check_input()`：命中注入只写 `turns.safety_flag`，不拦这一轮。
4. 写 user turn 并提交。
5. `db.refresh(sess)` 后按 `Turn.id` 顺序重建 history（依赖 relationship 的 `order_by`）。
6. 统计 user 轮数 `user_count`，调用 `chat_reply`（内部统一走 `llm.chat`）。
7. 平台安全拦截（`SafetyBlocked`）或回复质检不合格（`safety.check_reply`：出戏 / 超长 / 中文占比 / 提示词泄露）→ 换成预设追问，标 `replaced=True`，ai turn 的 `safety_flag="replaced"`。
8. 写 ai turn 并提交。
9. 返回 `{turn_index, ai_reply, is_follow_up: True, should_finish, degraded, replaced, flagged, asr_source, plan}`；`should_finish = agent.should_finish(plan, user_count)`：有目标时「3 个目标全达成且已聊 ≥3 轮」或「满 6 轮」为真，无目标的老会话回退 `user_count >= 4`。

`finish_session` / `finish_session_stream` 的完整流程（两者共用 `_finish_report`）：

1. 查会话并校验归属 → 404。
2. **幂等**：若 `sess.report` 已存在，直接返回该报告（不重复调模型、不重复计费）。
3. **至少一轮**：没有任何 user turn 时返回 400「还没有任何回答，先至少聊一轮再生成报告」。
4. 重建 history（**全量** `sess.turns`）。
5. 特征提取（两条来源合并）：
   - `fluency_features(全部 user 文本拼接)` → 词数、填充词、TTR、MTLD、句数、句长；
   - `speech_features(每轮词数列表, 每轮 audio 元信息)` → 录音时长、语速、发音速度、停顿次数/均值/占比。
6. `stage: scoring` → `generate_report`（模型给每维 band；RAG 先检索参考卡注入 prompt）。
7. `rules.apply_to_report()` 融合规则分（只压不抬），得到 `dimensions` / `bands` / `band` / `cefr` / `total_score` 与 `scoring_detail`。
8. `stage: critic` → 复盘目标达成度：`source=llm` 才调模型，示例报告只按关键词规则算。
9. `stage: coach` → 诊断教练（只对 `source=llm`）：函数调用最多 4 步，工具调用实时通过 `tool` 事件推送。
10. `stage: cards` → 写 `reports`（含 `plan_json`、`coach_json`），置 `sessions.status = "finished"`，按错句类型自动建学习卡，提交。
11. 返回 `ReportOut`；流式版在 `done` 事件里带完整报告。

> `finish` 已在 API 层做「至少一轮」校验，0 轮会 400；不再产出 68 分的 mock 报告。

`list_sessions` 按 `id` 倒序返回当前用户会话，支持 `limit` / `offset`（不传 `limit` 仍返回全部，兼容现有前端；`sessions.py:470-484`）；`total_score` 取自关联报告，未生成报告时为 `null`。

#### 4.7.5 统一模型调用层（`services/llm.py`）

所有模型请求收口到两个函数，业务层不再各自拼 URL：

| 函数 | 用途 | 关键行为 |
|---|---|---|
| `chat(llm, messages, *, temperature, max_tokens, timeout, json_mode, tools, tool_choice)` | 一次对话调用，返回 `choices[0].message` | 统一拼 `{base}/chat/completions`；`json_mode` 加 `response_format`；`tools` / `tool_choice` 透传；401/403 且用户自带 key → `UserKeyInvalid`；平台 400 `Content Exists Risk` 或 200 `refusal` → `SafetyBlocked`（不重试） |
| `chat_json(llm, messages, *, validate, retries=1, **kw)` | 结构化 JSON 调用 | 解析失败或 `validate` 抛 `ValueError` 时，把错误追回去重试一次；全部失败返回 `None`，由调用方降级；`UserKeyInvalid` / `SafetyBlocked` 照常上抛 |

- **`/chat/completions` 只剩 3 处**：`llm.chat()`（`:99`）、`llm.open_chat_stream()`（`:380`）、`routers/system.py` 的密钥连通性测试（`:59`）。新增调用一律走 `chat()` / `chat_json()`。
- **JSON 容错**：`_loads_json()` 取回复里第一个 JSON 对象，容忍前后解释文字；空 content（DeepSeek JSON 模式可能全空格）按失败处理。
- **官方主机专属参数**：`thinking: {"type": "disabled"}` 与 `safety_check: {"level": "high"}` 只在 `host == api.deepseek.com` 时追加；第三方兼容端点不认识，带上可能 400。
- **默认模型** `deepseek-flash`（`config.py:116`）。

#### 4.7.6 Agent 编排与工具（`services/agent.py` / `services/tools.py`）

- **Planner**：建会话时从场景任务清单里选 3 个目标，失败退回规则目标（按清单前三个）；`plan.source` 标 `llm` / `rule`。
- **Executor**：仍是流式对话，system prompt 注入「已覆盖 / 仍缺」的目标块与图片场景细节（`llm.system_prompt`）。
- **Critic**：出报告前只可收紧关键词命中（只压不抬），失败退回规则达成度。
- **诊断教练 `coach`**：模型自己选只读工具查资料，再给 1–3 条最该改的问题。上限：`COACH_MAX_STEPS=4` 步、每步 `COACH_MAX_TOOL_CALLS=3` 次调用、`COACH_MAX_PRIORITIES=3` 条；走满 4 步还在调工具时，强制 `tool_choice="none"` 收尾。
- **工具注册表**（`tools.py`）：6 个只读工具 `scene_checklist` / `get_frames` / `recent_weakness` / `lookup_word` / `grammar_card` / `search_knowledge`，统一 OpenAI function schema；模型传参按 schema 校验（多余参数丢弃、类型不对返回 `{"error": ...}`），工具异常只降级不冒泡。`recent_weakness` / `search_knowledge` 的 `db`、`user_id` 由服务端注入，模型传了也忽略。
- **防幻觉证据**：`_sanitize_coach` 要求 `fix_index` 必须落在本次编号内、`evidence.ref` 必须出现在本次工具结果里，否则删掉该条并标 `grounded=False`；教练结果落 `reports.coach_json`，旧报告为 `{}`，前端整块不渲染。

#### 4.7.7 知识检索 RAG（`services/rag.py`）

- **语料**：60 张语法卡 + 60 张口语卡 + 600 条词库（`library.grammar_cards()` / `spoken_items()` / `wordbank`），首次 `search` 时用 `bm25s` 建一次索引，常驻内存、不落盘、不下载模型。
- **分词**：英文小写单词 + 中文二元组，查询与语料共用。
- **评分注入**：`scoring._reference_cards()` 对每句用户发言检索 `k=2` 的语法/口语卡，按 `ref` 去重，**最多 8 张**写进评分 prompt；模型只能引用本次注入的 `rule_ref`，编造的 id 会被清空。
- **用户历史检索**：`search_user_history()` 现场用该用户的 `study_items` + 历史报告 `fixes` 建小 BM25（上限 300 张卡 / 10 份报告），不缓存、不跨用户。
- **降级**：`bm25s` 缺失、建索引失败、检索异常都只返回空列表，报告照常生成。
- **离线评测**：`python -m evaluation.rag_eval`，40 条学习者错句 vs「按语法组随机取卡」基线，结果见 §8.7。

#### 4.7.8 内容安全（`services/safety.py`）

| 能力 | 口径 |
|---|---|
| 输入注入检测 | 中英常见注入句式（ignore previous instructions / 忽略之前的指令 / system prompt / 你现在是 / act as / jailbreak）命中只打 `turns.safety_flag="injection"`，**不拦截** |
| 输出质检 | `check_reply()`：空回复、出戏（`as an AI` / `作为人工智能`）、超长（>600 字符）、中文占比 >0.3、泄露 system prompt 连续 8 词 → 替换为预设追问 |
| 图片校验 | 文件头判 JPEG / PNG / WebP，≤4 MiB；解码与压缩在浏览器完成，服务端只校验类型和大小 |
| 安全替换 | 流式场景无法撤回已推内容，`done.replaced=true` + 替换文本让前端覆盖气泡 |

#### 4.7.9 服务端语音转写（`services/asr.py`）

- 入口 `POST /api/asr`（multipart）：≤8 MiB、≤120 秒；接受 16-bit PCM 单声道 WAV（8 kHz / 16 k / 22.05 k / 24 k / 32 k / 44.1 k / 48 k 七档采样率）或 Ogg Opus。
- 官方主机 `api.deepseek.com` 走 `/tools/asr`；其他兼容端点走 `/audio/transcriptions`（`ASR_MODEL`，默认 `whisper-1`）。
- 错误码映射：400 `bad_audio`、408 `timeout`、413 `too_large`、429 `rate_limited`、503 `unavailable`、504 `gateway_timeout`；网络/解析失败分别记 `network` / `bad_json`。
- 任何失败都返回 `{"text": "", "source": "none", "reason": ...}`，由前端回退浏览器识别；成功时 `source` 为 `deepseek` 或 `compatible`。
- 音频只在内存里转发，不写文件、不落库。

#### 4.7.10 拍照生成场景（`routers/scenes.py`）

- `POST /api/scenes/from-image`：图片 ≤4 MiB（JPG/PNG/WebP），base64 后按 Vision 消息发给模型；官方主机强制 `model=deepseek-flash`，其他端点用用户当前模型。
- 输出裁剪：`context` ≤300 字且去尖括号、命中注入检测则丢弃；`key_vocab` ≤8 条；`opening` ≤300 字；`scene_id` 不在 6 个场景内时按关键词兜底（都没有落到 `cafe_order`）。
- 失败语义：未配置 key → 409；key 被拒 → 502 `key_invalid`；模型不支持图片 → 400 提示换 `deepseek-flash`；其他 → 502「这次没认出来，换张图再试」。
- 结果用于建会话：`context` / `key_vocab` 进 `sessions.plan_json`，开场白进首条 ai turn。



### 4.8 与 evaluation 包的耦合

`routers/sessions.py` 第 20 行直接 `from evaluation.features import ...`，即**后端运行时依赖仓库根目录下的 `evaluation/` 包**。为保证可导入，`backend/app/__init__.py` 在包初始化时把仓库根目录插入 `sys.path`：

```python
_ROOT = os.path.abspath(os.path.join(os.path.dirname(__file__), "..", ".."))
if _ROOT not in sys.path:
    sys.path.insert(0, _ROOT)
```

影响：

- 部署时必须保留 `backend/` 与 `evaluation/` 的兄弟目录关系，不能只拷 `backend/`。
- 好处是特征口径在"在线报告"和"离线验证"中完全一致，避免两套实现漂移。
- 代价是 `evaluation/` 从"离线工具"变成了"运行时依赖"，其代码质量要求随之提高。

### 5.2 JSON 字段结构

#### 5.2.1 `reports.dimensions_json`

```json
{"pronunciation": 70, "fluency": 78, "grammar_vocab": 74, "task_completion": 82}
```

键集合随作答方式变（纯打字 3 维、纯录音 4 维、混合 5 维），前端 `ReportDimensions.vue` 按固定顺序渲染，缺键则该项不显示。

#### 5.2.2 `reports.fixes_json`

```json
[
  {
    "original": "I am very interest in this job.",
    "better": "I'm very interested in this role.",
    "reason": "interest 是名词/动词；这里需要形容词 interested，搭配 in。",
    "error_type": "grammar",
    "natural": "",
    "rule_ref": "tenses-01",
    "rule": {"ref": "tenses-01", "kind": "grammar", "title": "…", "text": "…"}
  }
]
```

`rule_ref` / `rule` 阶段 2 新增：只保存本次 RAG 注入过的卡 id，模型编造的 id 会被清空。

#### 5.2.3 `reports.features_json`

来源两段，键集合如下（实测输出）：

| 键 | 来源 | 含义 | 示例 |
|---|---|---|---|
| `word_count` | 文本 | 总词数 | 25 |
| `filler_count` | 文本 | 填充词个数 | 0 |
| `filler_rate` | 文本 | 填充词/总词数 | 0.0 |
| `ttr` | 文本 | 类符形符比 | 0.84 |
| `mtld` | 文本 | MTLD 近似值 | 43.75 |
| `sentence_count` | 文本 | 句数（按 `.!?` 切分） | 2 |
| `mean_sentence_len` | 文本 | 平均句长 | 12.5 |
| `audio_duration_sec` | 音频 | 累计录音时长（秒） | 7.3 |
| `speech_rate_wpm` | 音频 | 语速（词/分钟，按总时长） | 205.48 |
| `articulation_rate_wpm` | 音频 | 发音速度（按有声时间） | 241.94 |
| `pause_count` | 音频 | 停顿次数（≥0.15s） | 3 |
| `mean_pause_sec` | 音频 | 平均停顿时长 | 0.243 |
| `pause_ratio` | 音频 | 停顿总时长/总时长 | 0.1 |

注意：

- 无音频时（如手动输入），只有文本类键 + `pause_count: 0`、`mean_pause_sec: 0.0`。
- 无用户发言时，仅 `{word_count: 0, pause_count: 0, mean_pause_sec: 0.0}`。
- `fluency_features` 本身也支持 `duration_sec`/`speech_rate_wpm`/`pause_count`/`mean_pause_sec`/`articulation_rate_wpm`/`pause_ratio`（当传入词级时间戳时），但后端**没有**传时间戳，故这些键实际由 `speech_features` 提供。同名键会被后者覆盖。
- 这些是**客观测量值**：它们是规则子分的输入（语速/停顿/填充词 → 流利度；MTLD/句长/复杂句 → 语言范围），与模型分融合后再落 `scoring_json`；不是只展示。
- 纯打字会话没有 `filler_count` / `filler_rate` / `pause_count` / `mean_pause_sec`（后端会主动删除），报告页也就不显示这几项。

#### 5.2.4 `turns.audio_json`

```json
{"duration_sec": 3.2, "speech_time_sec": 2.8, "pauses": [0.2, 0.32]}
```

由前端 `audio.ts` 在录音结束瞬间计算并随 `turn` 请求上报；无录音时为 `"{}"`。

#### 5.2.5 `reports.coach_json`（阶段 1）

```json
{
  "source": "llm",
  "priorities": [
    {"fix_index": 0, "title": "第三人称单数", "why": "…", "next_step": "…",
     "evidence": [{"tool": "grammar_card", "ref": "tenses-01"}], "grounded": true}
  ],
  "trace": [
    {"step": 1, "tool": "grammar_card", "args": {"query": "present simple"}, "ok": true,
     "ms": 2, "summary": "…", "result": "…"}
  ]
}
```

- `priorities` 最多 3 条，`fix_index` 指向 `fixes_json` 的下标；`evidence.ref` 必须出现在本次 `trace[].result` 里，否则该条 `grounded=false`。
- `trace` 保留每次工具调用的参数、耗时与结果摘要（结果截断 2000 字符），供报告页「诊断依据」展开。
- 教练失败 / 未配置 / 示例报告：`source=skipped` 或整块为 `{}`，前端不渲染。

#### 5.2.6 `ReportOut.transparency`（阶段 4，派生字段，不落库）

```json
{"model": "deepseek-flash",
 "safety": {"flagged_inputs": 1, "replaced_replies": 0},
 "scores": {"model_ratio": 74, "rule_ratio": 26},
 "coach": {"grounded": 2, "total": 3}}
```

- `model` 取 `scoring_json.model`；`safety` 从 `turns.safety_flag` 统计；`scores` 按各维 `weight_rule` 反算模型/规则占比；`coach` 是证据覆盖数。
- 示例报告（`source=mock`）返回 `null`，前端不渲染透明度卡。

### 5.3 数据约定

- **时间**：库里存**无时区 UTC**（`datetime.utcnow`），API 出口统一经 `timeutil.utc_iso()` 转成带 `Z` 的 ISO-8601（`2026-11-17T05:23:11Z`），前端按本地时区展示。
- **删除**：`sessions → turns`、`sessions → report` 配了级联删除；删除用户不会级联删会话（管理台删用户时显式清数据）。
- **枚举**：`role`、`status`、`difficulty` 均为普通字符串，靠代码约定而非数据库约束（`difficulty` 在入口白名单校验）。
- **字符串存储的 JSON**：`dimensions_json`、`band_json`、`fixes_json`、`features_json`、`scoring_json`、`plan_json`、`coach_json` 等都用 TEXT 存 JSON 字符串，读写统一 `json.dumps(..., ensure_ascii=False)` / `json.loads(... or 默认值)`。这样在 SQLite 里可直接用 `sqlite3` 检查，代价是无法用数据库 JSON 函数索引。

| 字段 | 说明 |
|---|---|
| `turn_index` | 本次发言是第几轮用户发言（从 1 开始） |
| `ai_reply` | AI 的回应，前端会朗读 |
| `is_follow_up` | 当前恒为 `true`（保留字段） |

| `replaced` | 本轮回复不是模型原文（安全拦截/质检不合格），已换成预设追问；前端用它覆盖气泡 |
| `flagged` | 本轮用户输入被安全标记（只标记，不影响回复） |
| `asr_source` | 本轮输入的转写来源：`cloud` / `browser`；打字轮为空 |
| `plan` | 当前会话的目标计划（`goals` / `achieved` / `missing`），前端用于展示目标进度 |

#### 6.3.12 服务端语音转写（阶段 3）

```
POST /api/asr
Content-Type: multipart/form-data
file=<WAV 或 Ogg Opus>
X-ASR-Model: <可选，覆盖非 DeepSeek 主机的模型名>
```

- 限制：文件 ≤8 MiB、WAV 时长 ≤120 秒、16-bit PCM 单声道、7 档合法采样率（8 k / 16 k / 22.05 k / 24 k / 32 k / 44.1 k / 48 k）；Ogg Opus 不解析时长。
- 成功：`{"text": "...", "source": "deepseek" | "compatible", "duration_ms": 3200}`。
- 失败：HTTP 200 + `{"text": "", "source": "none", "reason": "..."}`，前端据此回退浏览器识别；`reason` 取值 `bad_audio` / `timeout` / `too_large` / `rate_limited` / `unavailable` / `gateway_timeout` / `network` / `bad_json` / `empty`。
- 路由层错误：未配置 key → 409 `llm_not_configured`；用户 key 被拒 → 502 `key_invalid`；超 8 MiB → 413。

#### 6.3.13 拍照生成场景（阶段 3）

```
POST /api/scenes/from-image
Content-Type: multipart/form-data
file=<JPG / PNG / WebP，≤4 MiB>
```

响应 `200`：

```json
{"scene_id": "cafe_order", "scene_name": "咖啡店点单",
 "context": "你在咖啡店点单，菜单上有拿铁 4.5 美元…",
 "key_vocab": [{"term": "latte", "zh": "拿铁"}],
 "opening": "Hi there! What can I get for you today?"}
```

- 图片只在内存里 base64 后发一次 Vision 请求，不落盘、不入库。
- 裁剪：`context` ≤300 字（尖括号去掉、命中注入则丢弃）、`key_vocab` 3–8 条、`opening` ≤300 字。
- 错误：未配置 key → 409；key 被拒 → 502 `key_invalid`；模型不支持图片 → 400「换 `deepseek-flash`」；其他 → 502「这次没认出来，换张图再试」。

#### 6.3.14 知识检索（阶段 2）

```
GET /api/knowledge/search?q=present%20perfect&k=4
GET /api/knowledge/word?term=negotiate
```

- `search` 返回 `{"knowledge": [{ref, kind, title, text, score}], "history": [...]}`：`knowledge` 是内置语料（语法卡/口语卡/词库），`history` 是该用户自己的学习卡与历史错句（固定最多 3 条）。
- `q` 最多 200 字符；`k` 1–10，默认 4；空 `q` → 400。
- `word` 返回词库词条，查不到时 `{"found": false, "term": "..."}`，不 404；`term` 最多 64 字符。

### 7.4 API 客户端与流式

```js
rec.continuous = false      // 停顿即结束
```

- 仅 `window.SpeechRecognition || window.webkitSpeechRecognition` 存在时可用；不支持时提示"请用 Chrome，或点手动输入"。
- `onresult` 把 `event.results` 全部拼成一个字符串，相当于**只保留最终/最新转写**。
- Chrome 的 Web Speech API 实际使用云端识别，**需要联网**。

**② 朗读**（`utils/speech.ts` + 可选后端 TTS）

```js
utter.lang = 'en-US'; utter.rate = rate   // 页面「慢 / 正常 / 快」= 0.85 / 1.0 / 1.15
window.speechSynthesis.cancel()            // 新语音打断旧语音
```

- 默认走浏览器 `speechSynthesis`，不需要任何 key。每条 AI 消息旁有 🔊 按钮可重听。
- 设置页可填**可选的语音合成密钥**（`X-TTS-Key / X-TTS-Base-URL / X-TTS-Model / X-TTS-Voice`，只存浏览器）。
  前端先试 `POST /api/tts`，**任何失败（含未配置）都回落 `speechSynthesis`**——TTS 挂了不能连朗读一起没。
- 错误码：`409 tts_not_configured` / `502 tts_key_invalid` / `502 tts_unavailable`；`TTS_API_KEY` 只是 `.env` 兜底。
- 兼容 OpenAI 兼容的 `/audio/speech`；讯飞/火山那种 AppID+Secret 三件套不在本契约内。

**③ 录音包络 → 语速/停顿**（`utils/audio.ts`）

- `getUserMedia({audio:true})` + `AudioContext` + `AnalyserNode`（`fftSize=1024`）。
- 每 50ms 采样一次时域数据，算 RMS；**RMS > 0.02 视为有声**。
- 有声段累计为 `speech_time`；从有声转无声记为静音起点，下一次转有声时若静音时长 ≥ 0.15s 则记入 `pauses`。
- `stop()` 返回 `{duration_sec, speech_time_sec, pauses}`，全部保留 2 位小数。
- 麦克风权限被拒时 `startAudioCapture` 抛错，`Practice.vue` 捕获后置 `capturer = null`，**对话仍可继续**（只是没有音频特征）。这是有意的降级设计。

> 阈值 0.02 与 0.15s 是硬编码常量，在不同麦克风/噪声环境下表现差异较大，属于后续可配置项。

**④ 服务端转写（阶段 3，`utils/wav.ts` + `composables/useRecorder.ts`）**

- 录音（webm/opus）先在浏览器里用 `wav.ts` 解码重采样成 **16 kHz 单声道 16-bit WAV**，再 `POST /api/asr`。
- 成功：用返回文本，`asr_source="cloud"`；失败（`source=none`）或超时：回退浏览器识别，`asr_source="browser"`。
- 音频只在内存里走一遍，服务端不写文件、不入库；原始录音仍只进浏览器 IndexedDB。

## 8. 评估与验证子系统

### 8.1 目标

回答两个问题：

1. **信度**：不同人评之间是否一致？（`ICC(2,1)`、`ICC(2,k)`、Pearson/Spearman、Cohen/Fleiss kappa）
2. **效度**：系统分与人评是否对得上？（Pearson/Spearman、MAE/RMSE、Bland-Altman）

### 8.3 统计量实现要点

| 函数 | 实现 | 备注 |
|---|---|---|
| `pearson(x, y)` | 标准协方差公式 | `n<2` 或方差为 0 → `nan` |
| `spearman(x, y)` | 先 `_ranks` 再 Pearson | `_ranks` 处理并列（取平均秩），实现正确 |
| `mae` / `rmse` | 绝对误差均值 / 均方根 | 需等长输入 |
| `bland_altman(a, b)` | `diff = a - b`，均值差 ± 1.96×SD | 返回 `n/mean_diff/sd_diff/loa_lower/loa_upper/within_loa/within_loa_ratio` |
| `cohens_kappa(r1, r2)` | `(po - pe) / (1 - pe)` | `pe >= 1` 时返回 1.0 |
| `fleiss_kappa(ratings)` | 行=样本、列=评分者 | 支持 2 人以上；每行人数必须一致 |
| `_icc(matrix, average)` | 双向 ANOVA，手算 `SS_rows/SS_cols/SS_err` | `average=False` → ICC(2,1) 绝对一致性；`average=True` → ICC(2,k) |
| `interpret_icc` / `interpret_kappa` | 区间映射为中文等级 | `nan` → "无法计算" |

ICC(2,1) 分母：`MSR + (k-1)MSE + k(MSC - MSE)/n`；ICC(2,k) 分母：`MSR + (MSC - MSE)/n`。与 Shrout & Fleiss (1979) 的两向随机、绝对一致性模型一致。

解释区间采用文献常见口径：ICC 用 Koo & Li (2016)，kappa 用 Landis & Koch (1977)。**这些区间是领域惯例，不是硬性阈值**，报告中应同时给出原始数值。

### 8.4 特征提取口径

`features.py` 只依赖标准库：

```python
FILLERS = {"um","uh","erm","hmm","mm","ah","like","well","actually","basically"}
_TOKEN_RE = re.compile(r"[A-Za-z']+")
```

- **分词**：只保留英文字母与撇号，小写化。中文、数字、标点被丢弃——这对英语口语场景是合理的，但意味着**中文夹杂内容不计入词数**。
- **填空词**：上表固定集合。`like`/`well` 在句中作实义词时也会被误计，属已知误差。
- **TTR**：`len(set(tokens)) / n`。
- **MTLD**：近似实现。以 `threshold=0.72`、`min_tokens=10` 累积，TTR 跌破阈值即计一个 factor 并重置；正反两遍取平均，最后 `n / factors`。与标准 MTLD 完全一致的前向/后向顺序细节略有差异，宜标注"近似"。
- **句数**：按 `[.!?]+` 切分后去空白。
- **`fluency_features(transcript, word_timings=None, pause_threshold=0.3)`**：`word_timings` 可选。传入时额外产出 `duration_sec`、`speech_rate_wpm`、`pause_count`、`mean_pause_sec`、`articulation_rate_wpm`、`pause_ratio`。
- **`speech_features(turn_word_counts, audio_metas, pause_min=0.15)`**：把每轮录音元信息求和后折算。语速按"总词数 / 总时长"，发音速度按"总词数 / 有声时长"，停顿占比按"停顿总时长 / 总时长"。

> 口径一致性：线上报告与离线验证共用同一份 `features.py`，这是刻意的设计（见 4.8）。但两处实现共享同一个近似 MTDL，误差也会被同时继承——写论文/答辩时应说明这是"轻量可解释指标"，不是 Praat 级别的声学分析。

## 9. 评分体系设计

> 完整的量表、锚点与校准记录见 [rubric-band.md](rubric-band.md)；本节只讲**怎么算**，数值口径以代码为准。

### 9.1 维度集合随作答方式变化

| 维度 | 键 | 出现条件 | 证据来源 |
|---|---|---|---|
| 发音清晰度 | `pronunciation` | 有录音轮 | 仅模型按转写推断（本项目不做声学测评） |
| 流利度 | `fluency` | 有录音轮 | 模型 + 规则分（语速/停顿/填充词） |
| 语法词汇 | `grammar_vocab` | 恒有 | 模型 + 规则分（复杂度） |
| 任务完成度 | `task_completion` | 恒有 | 模型 + 规则分（场景清单命中） |
| 文字表达 | `written_expression` | 有打字轮 | 仅模型（书面组织与用词） |

> 报告页这一维的标题固定显示「发音清晰度」（`Report.vue:43` 的维度标签），这是给人看的栏目名，**不代表声学清晰度测量**：分数由模型依据转写文本推断，规则层没有发音证据（`rules.py:363-371`）。

纯打字 3 维、纯录音 4 维、混合 5 维。**后端会把模型多给的维度丢掉**：打字轮不进发音/流利度，录音轮不进文字表达（`rules.py:343-347`）。
混合会话里填充词只从录音轮统计（纯打字的 `features` 里干脆没有 `filler_rate` 等字段）。

### 9.2 综合分：按模式加权，不是模型直给

| 作答模式 | pronunciation | fluency | written_expression | grammar_vocab | task_completion |
|---|---|---|---|---|---|
| `voice` | 20 | 20 | — | 30 | 30 |
| `typed` | — | — | 35 | 35 | 30 |
| `mixed` | 15 | 15 | 20 | 25 | 25 |

权重在 `evaluation/bands.py:33-52`（`DIMENSION_WEIGHTS`），由 `rules.py:419-420` 调用；缺失维度按剩余权重重新归一，不当 0 分；认不出模式才退回等权平均。
综合分与 band 由代码算出并落库，**不再是模型给一个 `total` 就存**——旧稿那句「总分由模型直接给出、与四维可能不自洽」已作废。

### 9.3 模型分与规则分怎么融合

1. **模型先给 band**：每个维度按雅思描述语给 0.5 步长的 band，再 `S = 10B + 10` 换 0–100（全项目唯一换算入口 `evaluation/bands.py`）。
2. **规则分**（可复现，纯标准库）：
   - 流利度 = `0.40·f_wpm + 0.35·f_pause + 0.25·f_filler`，映射到 45–90；没有录音则无规则分（不拿填充词硬凑）。
   - 语言复杂度 = `0.45·f_mtld + 0.35·f_msl + 0.20·f_cx`；无标点且无停顿估计时，句长项的 0.35 权重让给从句标记。
   - 任务完成 = `40 + 60 × 场景清单命中率`。
3. **单维融合权重**（规则:模型）：发音 0:1、流利度 0.5:0.5、语法 0.35:0.65、任务 0.6:0.4、文字表达 0:1。
4. **只压不抬**：模型比规则分高 **>20 分**时压回 `rule + 10`（`CLAMP_GAP / CLAMP_TO`）；规则分显著高于模型（>20）不抬分，只在报告里标「请人工复核」。
5. **可复现**：每维的 `model_score / rule_score / final_score / clamped / clamp_reason` 和参与计算的输入一起写进 `reports.scoring_json`，
   接口出参字段名是 `scoring_detail`（注意这两个名字不同，查库/查响应别搞混）。
6. **RAG 参考卡（阶段 2）**：评分前先按用户每句发言检索语法/口语卡，去重后**最多 8 张**写进 prompt；模型只能把本次注入的卡 id 填进 `rule_ref`，编造的 id 会被 `_sanitize_fixes()` 清空，卡原文随 `fix.rule` 一起返回（`scoring.py:43-107`、`:206-272`）。
7. **结构化重试**：评分调用走 `chat_json(validate=_validate_report, retries=1)`（`scoring.py:300-309`），JSON 不合法或维度不是数字时把错误追回去重试一次，仍失败才降级。

### 9.4 档位、跨模式可比与降级

- **取整**：`B = (S−10)/10`，`floor(B×2+0.5)/2`；0–100 总分与维度分统一取整 `floor(x+0.5)`（62.5→63、67.5→68；`bands.py:140-146`、`rules.py:412-416`）；`S < 40` 不给 band（显示「低于 A2」）；CEFR 按 B1=4.0–5.0、B2=5.5–6.5、C1=7.0–8.0 归段。
- **两个 band 别混**：报告页的 `band` 是本模式加权分的档位，历史/成长曲线的 `comparable_band` 只取两种作答都评的两个共享维度（语法词汇 + 任务完成），用于跨模式比较。
  同一场混合会话，两个值差 0.5 是正常的，不是自相矛盾——报告页应标明是本模式口径。
- **降级**：模型不可用时 `source=mock`，`total_score / band / cefr` 全为 `null`，`mock_reason` 取 `unavailable`（超时、不可达、解析失败）或 `not_configured`（中途丢 key）；`invalid_key` 仅在服务端 `.env` 兜底密钥被拒时出现（用户自己的 key 被拒走 502 `key_invalid`，不生成报告）。
  报告标「示例报告（模型不可用）· 本次不计分」，`sentence_fixes` 只列用户真实说过的句子，不写死任何示例句。
- **改写硬校验**：模型给的 `original` 必须能在该用户转写里找到（忽略大小写与标点），找不到直接丢弃——防模型编句子。
- **约束**：输出纯 JSON、`temperature=0.2`、`sentence_fixes` 1–3 条；中文写 `comment` / `reason`，英文保留 `original` / `better`。

### 9.5 可测指标与分数的关系（与旧稿的区别）

旧稿写的是「语速/停顿/TTR/MTLD 只展示、不参与打分」。**现在它们参与规则分并与模型分融合**（见 9.3），所以：
报告页的「评分依据（可复现）」能当场把某一维的规则分、模型原分、压分原因摊开算——这是评审最容易追问、也最容易验证的一块。
仍然不声称的是：没有声学/音素级测评，发音维只有文本推断；规则权重在**真实人工标注数据上尚未校准**，`evaluation/demo_data.csv` 是合成数据，只证明脚本通路。

### 10.4 生产部署现状与建议

**现状**：只有开发形态。`frontend/dist/` 虽已构建，但**后端不托管该产物**，`vite preview` 也不在启动脚本中。因此：

- `dist` 里的 `index.html` 引用的是 `/assets/...` 绝对路径，若直接交给静态服务器托管，`/api` 无人代理会全部 404。
- 目前"部署"等同于"在演示机上跑两个 dev 进程"。

**建议的最小方案**（三选一）：

1. **Nginx 反代**：静态托管 `dist/`，`location /api { proxy_pass http://127.0.0.1:8000; }`。
2. **后端托管静态**：在 `main.py` 里 `app.mount("/", StaticFiles(directory="../frontend/dist", html=True))`，但需把它放在所有 `/api` 路由注册**之后**，否则会吞掉 API 路由。
3. **Docker Compose**：两个服务 + 一个 Nginx。

无论哪种，都需要处理 SPA 的 history 路由回退（未匹配路径返回 `index.html`），否则 `/report/1` 直接刷新会 404。

## 附录 D：v1.0 → v2.0 主要变更

v1.0 写于 2026-10-29 上午，之后代码又走了 band、打字分流、练习增强、账号安全四大块。以下是本文档这一版按代码改掉的内容，

| 主题 | v1.0 的说法 | v2.0（当前代码） |
|---|---|---|
| 评分产物 | 模型直接给 `total_score`，四维只是展示 | 模型给每维 band → 规则分融合（只压不抬）→ 按作答模式加权算综合分，明细落 `scoring_json` |
| 维度数 | 固定四维 | 3/4/5 维，随作答方式变；打字轮不计发音/流利度，录音轮不计文字表达 |
