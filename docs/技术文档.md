## 1. 项目概述

### 1.1 定位

SpeakPal 是一个**场景化的 AI 英语口语诊断陪练**：学习者注册登录后，选择一个真实场景（求职面试 / 咖啡店点单 / 雅思 Part 1），与 AI 角色进行多轮**语音**对话；对话结束后，系统给出综合分、四个维度分、逐句"更地道说法"的纠错报告，以及与本次对话相关的流利度客观指标。

与同类"陪聊"产品的差异点在于**可验证**：系统的评分结论不是自说自话，而是配有 `evaluation/` 验证层，用 ICC、kappa、Bland-Altman、MAE/RMSE 等统计量与人评金标准对齐，且脚本可复现。

### 1.2 核心能力

| 能力 | 实现方式 | 入口 |
|---|---|---|
| 注册 / 登录 | 用户名密码 + PBKDF2-SHA256 散列 + JWT | `POST /api/auth/register`、`POST /api/auth/login` |
| 场景选择 | 后端内置 3 个场景定义 | `GET /api/scenes` |
| 多轮对话 | 大模型按角色设定推进，保留最近 8 轮上下文 | `POST /api/sessions/{id}/turn` |
| 语音输入 | 浏览器 Web Speech API 转写 | 前端 `src/utils/speech.js` |
| AI 朗读 | `speechSynthesis` | 同上 |
| 发音/流利度客观指标 | Web Audio 包络分析 + 文本特征提取 | `src/utils/audio.js`、`evaluation/features.py` |
| 评分报告 | 大模型按 rubric 输出 JSON，落库 | `POST /api/sessions/{id}/finish` |
| 逐句纠错 | 报告中的 `sentence_fixes` | `GET /api/sessions/{id}/report` |
| 历史记录 | 按 `user_id` 隔离 | `GET /api/sessions` |
| 运营后台 | 单页 HTML + 管理密钥 | `GET /`、`GET /admin` |
| 评分可验证 | 纯标准库统计工具 + CLI | `python -m evaluation.validate` |

### 1.3 非目标与边界

以下内容**不在**当前实现范围内，文档中相关表述不得被理解为已具备：

- 不是专业声学测评：发音维度由大模型**依据转写文本推断**，报告中固定标注"分数由 AI 估算，仅供参考"。
- 不做音频存储：只保存录音的**统计元信息**（时长、停顿），不保存音频文件本身。
- 无真实人工评分数据：`evaluation/demo_data.csv` 是固定随机种子生成的合成数据，仅用于验证脚本可跑通，不构成任何有效性结论。
- 无多租户/班级/作业体系，无教师端；管理台只做只读统计。
- 无自动化测试套件（见 [12. 已知限制](#12-已知限制与技术债)）。

## 2. 术语与缩写

| 术语 | 含义 |
|---|---|
| Session（练习会话） | 一次从选择场景到生成报告的完整练习，对应 `sessions` 表一行 |
| Turn（轮次） | 会话中的一条消息，`role` 为 `ai` 或 `user`，对应 `turns` 表一行 |
| Report（报告） | 会话结束后生成的评分结果，与 Session 一对一，对应 `reports` 表一行 |
| rubric | 评分量表，本系统为四维 0–100 分 |
| ICC | 组内相关系数（Intraclass Correlation Coefficient），衡量评分者一致性 |
| kappa | 类别型一致性系数，本系统用于 A/B/C 档位 |
| Bland-Altman | 两种测量方法一致性的偏差分析（均值差 + 95% 一致性界限 LoA） |
| MTLD | 词汇多样性指标（Measure of Textual Lexical Diversity），此处为近似实现 |
| TTR | Type-Token Ratio，类符/形符比 |
| mock | 未配置大模型密钥时的内置假数据回复，保证流程可跑通 |

┌───────────────▼──────────────────────────────────────────────┐

│  ├─ routers/   admin · auth · scenes · sessions · reports      │
│  ├─ services/  scenes（场景定义）· llm（对话）· scoring（评分）  │

┌───────▼────────────┐        ┌─────────▼──────────────────────┐
│  SQLite            │        │  大模型 API                     │
│  backend/speakpal.db│       │  （DeepSeek / 任意兼容端点；可空）│

┌──────────────────────────────────────────────────────────────┐

### 3.2 运行时拓扑

| 进程 | 端口 | 启动方式 | 说明 |
|---|---|---|---|
| uvicorn 后端 | 127.0.0.1:8000 | `start-backend.bat` / `start-backend.ps1` | 提供 API、后台控制台、`/docs` |
| Vite dev server | 127.0.0.1:5173 | `start-frontend.bat` / `start-frontend.ps1` | 提供 SPA，`/api` 反代到 8000 |
| 浏览器 | — | `start-all.bat` 自动打开 | 语音功能**仅 Chrome** 可用 |

前端与后端是**两个独立进程**，通过 HTTP 通信；开发期依赖 Vite 代理消除跨域，生产部署形态见 [10.4](#104-生产部署现状与建议)。

### 3.3 技术选型与理由

| 层 | 选型 | 版本约束 | 选择理由 |
|---|---|---|---|
| 前端框架 | Vue 3 + `<script setup>` | `^3.5.0` | 组合式 API 代码量小，单文件组件适合小团队 |
| 构建 | Vite | `^5.4.0` | 冷启动快，内置代理，零配置支持 Vue |
| 样式 | Tailwind CSS | `^3.4.10` | 原子类，避免维护独立 CSS 文件；`style.css` 仅 3 行 `@tailwind` + body 基础样式 |
| 路由 | vue-router（history 模式） | `^4.4.0` | SPA 常规方案 |
| 状态 | Pinia（setup store 写法） | `^2.2.0` | 与 Vue3 组合式 API 一致 |
| HTTP | axios | `^1.7.0` | 拦截器便于统一注入 token、统一处理 401 |
| 后端框架 | FastAPI | `>=0.110`（实测 0.162.0） | Pydantic 校验 + 自动 OpenAPI，`/docs` 可直接当接口文档 |
| ORM | SQLAlchemy 2.x | `>=2.0`（实测 2.1.6） | 声明式模型，便于换库 |
| 数据库 | SQLite | 内置 | 零运维，校赛场景足够；通过 `DATABASE_URL` 可切换 |
| 鉴权 | PyJWT（HS256） | `>=2.8` | 无状态，前端存 localStorage 即可 |
| 大模型调用 | httpx + OpenAI 兼容 REST | `>=0.27` | 不绑定厂商 SDK，改 `LLM_BASE_URL` 即换供应商 |
| 统计 | 纯标准库 `math` | — | 避免引入 numpy/scipy，保证"评审机器上开箱可跑" |

**关键取舍**：`evaluation/` 刻意不依赖第三方统计库。`agreement.py` 手写了方差分析（ANOVA）来算 ICC，代价是代码需要自行校验，收益是在任何 Python 3 环境下都能复现结果——这正是"可验证"命题成立的前提。

### 3.4 代码分层与依赖方向

```
routers/ ──► services/ ──► config
   │            │
   ├──► models/ ──► db ──► config
   ├──► schemas（Pydantic DTO）
   ├──► security ──► models, db, config
   └──► evaluation.features（跨包复用，见 4.8）
```

约定：

- `routers/` 只做参数校验、权限判断、编排，不写业务规则。
- `services/` 不接触 `Request`/`Response`，只接收纯 Python 结构（`dict`、`list`），因此可单独测试与复用。
- `schemas.py` 是所有对外 JSON 形状的唯一定义处，`ReportOut`、`TurnOut` 等均由它约束。

### 3.5 端到端数据流（一次完整练习）

```
用户操作            前端                    后端                      外部
────────────────────────────────────────────────────────────────────────────
输入账号密码   →  Login.vue submit()
                  api.post('/auth/login') → 校验 PBKDF2 → 签发 JWT
                  auth.setAuth()            ← {token, user}
                                          
选场景+难度    →  Home.vue start()
                  api.post('/sessions')  → get_scene() 校验
                                           INSERT sessions + 首条 ai turn
                  session.start(...)        ← {session_id, opening_question}
              →  跳转 /practice，朗读开场白（speechSynthesis）

按麦克风说话   →  createRecognizer() + startAudioCapture()
                  (Web Speech API 转写)   (Web Audio 计算时长/停顿)
                  api.post('/sessions/{id}/turn') → 写 user turn
                                           → chat_reply()  ──httpx──► LLM
                                           INSERT ai turn
                  speak(ai_reply)           ← {turn_index, ai_reply, should_finish}
                  （重复 N 轮）

点"结束并出报告" → api.post('/sessions/{id}/finish')
                                           → generate_report() ──httpx──► LLM
                                           → fluency_features() + speech_features()
                                           INSERT reports，sessions.status=finished
                  router.push('/report/:id') ← ReportOut
              →  Report.vue 渲染分数/维度/特征/纠错

看历史         →  api.get('/sessions')   → 按 user_id 查询 + 关联 report
```

## 4. 后端设计

### 4.1 应用入口与中间件

`backend/app/main.py` 是唯一入口，职责如下：

| 顺序 | 代码 | 作用 |
|---|---|---|
| 1 | `Base.metadata.create_all(bind=engine)` | 启动时建表（幂等） |
| 2 | `_ensure_schema()` | 轻量"迁移"：缺列则 `ALTER TABLE` 补齐 |
| 3 | `FastAPI(..., docs_url=None, redoc_url=None)` | 关闭内置文档，改用本地 Swagger 资源 |
| 4 | `app.mount("/static", StaticFiles(...))` | 提供 `admin.html` 与 Swagger bundle |
| 5 | `CORSMiddleware` | 全开跨域 |
| 6 | `include_router(...)` × 5 | 注册 admin / auth / scenes / sessions / reports |
| 7 | `GET /docs` | 自定义 Swagger UI（引用本地 JS/CSS，离线可用） |
| 8 | `GET /`、`GET /admin` | 直接返回 `static/admin.html` 文本 |
| 9 | `GET /api/health` | 健康检查 `{"status": "ok"}` |

**Schema 演进机制**：项目未引入 Alembic。`_ensure_schema()` 通过 `inspect(engine)` 检查列是否存在，对 `reports.features_json` 和 `turns.audio_json` 执行一次 `ALTER TABLE ... ADD COLUMN`。这是 v0.1 → v0.2 的向后兼容手段，适用于"只加列"的变更；删除列、改类型、加约束需手工处理。

> 实测确认：现有 `backend/speakpal.db` 已含 `features_json`、`audio_json` 两列，迁移逻辑已在真实库上执行过。

### 4.2 配置

`backend/app/config.py` 用 `python-dotenv` 在导入时加载 `backend/.env`（相对当前工作目录，因此**必须从 `backend/` 目录启动**，启动脚本已保证这点）。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `JWT_SECRET` | `dev-secret-change-me` | JWT 签名密钥，**生产必须替换** |
| `JWT_ALGORITHM` | `HS256`（代码内固定） | 不可通过环境变量修改 |
| `JWT_EXPIRE_MINUTES` | `10080`（7 天） | token 有效期 |
| `DATABASE_URL` | `sqlite:///./speakpal.db` | 相对 `backend/` 解析 |
| `LLM_API_KEY` | 空 | **为空时全链路自动 mock** |
| `LLM_BASE_URL` | `https://api.deepseek.com/v1` | OpenAI 兼容端点 |
| `LLM_MODEL` | `deepseek-chat` | 模型名 |
| `ADMIN_KEY` | `admin123` | 管理台密钥，明文比较 |

`.env` 已在 `.gitignore` 中，不会入库；仓库只提供 `.env.example`。

### 4.3 数据访问

`backend/app/db.py`：

- `create_engine(settings.database_url, connect_args={"check_same_thread": False})`——仅当 URL 以 `sqlite` 开头才加该参数（SQLite 多线程访问需要）。
- `SessionLocal = sessionmaker(autocommit=False, autoflush=False)`。
- `get_db()` 为 FastAPI 依赖，`yield` 后 `close()`，保证每请求一个 Session 且异常时也能释放。

### 4.4 数据模型

`backend/app/models.py` 共 4 张表。

```
users 1 ──── n sessions 1 ──── n turns
                    │
                    └──── 1 reports（session_id 唯一约束 → 一对一）
```

| 表 | 主键 | 关键约束 | 关系 |
|---|---|---|---|
| `users` | `id` | `username` 唯一且索引 | `sessions` 反向引用 |
| `sessions` | `id` | `user_id` 外键 + 索引 | `turns`（级联删除，按 id 排序）、`report`（一对一，级联删除） |
| `turns` | `id` | `session_id` 外键 + 索引；`role ∈ {ai, user}`（无数据库级枚举） | 属于 session |
| `reports` | `id` | `session_id` 唯一 + 外键 | 一对一 session |

### 4.5 鉴权与安全

`backend/app/security.py`：

| 能力 | 实现 | 细节 |
|---|---|---|
| 口令散列 | `hash_password` | 16 字节随机盐 + `pbkdf2_hmac("sha256", …, 120000)`，存为 `base64(salt)$base64(dk)` |
| 口令校验 | `verify_password` | 重新派生后 `hmac.compare_digest`，常量时间比较；任何异常返回 `False` |
| 签发 | `create_token` | payload = `{sub: str(user_id), iat, exp}` |
| 校验 | `get_current_user` | `HTTPBearer(auto_error=False)` 取头；`jwt.decode` 失败统一 401；再查库确认用户仍存在 |

**错误语义**（实测）：

| 场景 | 状态码 | `detail` |
|---|---|---|
| 无 `Authorization` 头 | 401 | 未登录 |
| token 无效/过期 | 401 | 登录已失效，请重新登录 |
| token 指向已删除用户 | 401 | 用户不存在 |
| 管理密钥错误 | 401 | 管理密钥错误 |

**安全现状与风险**（详见 [12](#12-已知限制与技术债)）：

- `ADMIN_KEY` 明文比较，默认值 `admin123` 写在前端提示与 README 中，属公开默认口令。
- `JWT_SECRET` 有公开默认值。
- 管理密钥被前端存放在 `localStorage.admin_key`。
- CORS 为 `allow_origins=["*"]` 且 `allow_credentials=True`：Starlette 在该组合下会回显 `*`，浏览器规范不允许 `*` 与凭证共存。本项目用 `Authorization` 头而非 Cookie，实际功能不受影响，但配置本身应修正为具体来源。

### 4.6 路由层

| 文件 | 前缀 | 标签 | 鉴权 | 职责 |
|---|---|---|---|---|
| `routers/auth.py` | `/api/auth` | auth | 部分 | 注册、登录、取当前用户 |
| `routers/scenes.py` | `/api` | scenes | 用户 | 列出场景（对外隐藏 `role`/`opening` 等内部字段） |
| `routers/sessions.py` | `/api` | sessions | 用户 | 建会话、加轮次、结束出报告、历史列表 |
| `routers/reports.py` | `/api` | reports | 用户 | 读取已生成报告 |
| `routers/admin.py` | `/api/admin` | admin | 管理密钥 | 全局统计、用户概览、最近会话 |

所有会话类接口都做**归属校验**：`sess.user_id != user.id` 时返回 404（而非 403），避免泄露会话是否存在。

### 4.7 服务层

#### 4.7.1 场景定义（`services/scenes.py`）

场景是硬编码的 Python 列表，共 3 个，每个含 `id/name/icon/desc/role/opening`：

| id | 名称 | 角色设定 `role` | 开场白 `opening` |
|---|---|---|---|
| `job_interview` | 求职面试 | a friendly technical interviewer… | Hi, thanks for coming in today. Could you tell me a bit about yourself? |
| `cafe_order` | 咖啡店点单 | a barista at a busy coffee shop | Hi there! What can I get for you today? |
| `ielts_part1` | 雅思 Part 1 | an IELTS speaking examiner | Let's talk about where you live. Do you live in a house or an apartment? |

`public_scenes()` 只输出前 4 个字段，避免把 prompt 用的角色设定暴露给前端。新增场景只需往 `SCENES` 追加一项，但 `llm.py` 的 `MOCK_FOLLOW_UPS` 需同步补 mock 追问，否则降级时只会重复 "Could you tell me more about that?"。

#### 4.7.2 对话服务（`services/llm.py`）

- **入口**：`chat_reply(scene, difficulty, history, turn_index) -> str`
- **降级**：`settings.llm_api_key` 为空 → 直接返回 `MOCK_FOLLOW_UPS[scene_id][turn_index]`（索引被 clamp 到列表长度内，不会越界）。
- **真实调用**：System prompt 规定"一次只问一个问题、先回应再追问、**对话中不纠错**（纠错留到报告）"；history 只取最近 8 条；`temperature=0.7`；超时 30s。
- **异常处理**：任何异常（含 4xx/5xx、超时、解析失败）都**静默回退 mock**，不抛出、不记录日志。

```python
# 关键 prompt 约定
f"You are {scene['role']}. The user is an English learner practicing speaking.\n"
"Ask short, natural, conversational questions. Ask only one question at a time.\n"
"After the user answers, briefly acknowledge, then ask one relevant follow-up.\n"
"Do not correct grammar during the conversation; correction is handled later.\n"
```

"对话中不纠错"是重要的产品决策：口语练习的连续性优先于即时纠错，纠错统一放在报告里，避免打断表达。

#### 4.7.3 评分服务（`services/scoring.py`）

- **入口**：`generate_report(scene, difficulty, history) -> dict`
- **真实调用**：单条 user message 承载整个 prompt；`temperature=0.2`（求稳定）；超时 60s；用 `re.search(r"\{.*\}", text, re.S)` 从回复中抠出第一个 JSON 块，`json.loads`；失败即回退 mock。
- **输出契约**（prompt 中强约束）：

```json
{
  "total": 0,
  "dimensions": {"pronunciation": 0, "fluency": 0, "grammar_vocab": 0, "task_completion": 0},
  "sentence_fixes": [{"original": "", "better": "", "reason": ""}],
  "comment": "",
  "note": "分数由 AI 估算，仅供参考。"
}
```

- **语言约定**：`comment` 与每条 `reason` 用简体中文；`original`/`better` 保持英文。
- **发音免责**：prompt 明确 `pronunciation is an estimate based on the transcript; do not claim precise acoustic analysis`。
- **mock 基线**：`base = 68 + min(用户轮数 × 4, 16)`，四维在 base 上做 ±6 偏移并裁剪到 0–100。实测：0 轮 → 总分 68、四维 62/70/66/74；1 轮 → 72；≥4 轮 → 84 封顶。

> ⚠️ 静默降级是该模块最大的可观测性缺口：线上如果 API key 失效，用户仍会拿到一份"看起来正常"的 mock 报告，且没有任何字段能区分。建议在报告中增加 `source: "llm" | "mock"` 并打日志。

#### 4.7.4 轮次与报告编排（`routers/sessions.py`）

`add_turn` 的完整流程：

1. 查会话并校验归属 → 404；状态非 `active` → 400「会话已结束」。
2. 若带 `audio`，序列化为 JSON 写入 `turns.audio_json`。
3. 写 user turn 并提交。
4. `db.refresh(sess)` 后按 `Turn.id` 顺序重建 history（依赖 relationship 的 `order_by`）。
5. 统计 user 轮数 `user_count`，调用 `chat_reply`。
6. 写 ai turn 并提交。
7. 返回 `{turn_index: user_count, ai_reply, is_follow_up: True, should_finish: user_count >= 4}`。

`finish_session` 的完整流程：

1. 查会话并校验归属 → 404。
2. **幂等**：若 `sess.report` 已存在，直接返回该报告（不重复调模型、不重复计费）。
3. 重建 history，调用 `generate_report`。
4. 特征提取（两条来源合并）：
   - `fluency_features(全部 user 文本拼接)` → 词数、填充词、TTR、MTLD、句数、句长；
   - `speech_features(每轮词数列表, 每轮 audio 元信息)` → 录音时长、语速、发音速度、停顿次数/均值/占比。
5. 写 `reports`（`total_score` 取整），置 `sessions.status = "finished"`，提交。
6. 返回 `ReportOut`。

> ⚠️ `finish` 不做"至少一轮对话"的前置校验，0 轮也能出报告（实测通过，得分为 68 分的 mock 结果）。前端虽然限制了交互路径，但 API 层没有防护。

`list_sessions` 按 `id` 倒序返回当前用户全部会话，**无分页**；`total_score` 取自关联报告，未生成报告时为 `null`。

### 4.8 与 evaluation 包的耦合

`routers/sessions.py` 第 20 行直接 `from evaluation.features import ...`，即**后端运行时依赖仓库根目录下的 `evaluation/` 包**。为保证可导入，`backend/app/__init__.py` 在包初始化时把仓库根目录插入 `sys.path`：

```python
_ROOT = os.path.abspath(os.path.join(os.path.dirname(__file__), "..", ".."))
if _ROOT not in sys.path:
    sys.path.insert(0, _ROOT)
```

影响：

- 部署时必须保留 `backend/` 与 `evaluation/` 的兄弟目录关系，不能只拷 `backend/`。
- 好处是特征口径在"在线报告"和"离线验证"中完全一致，避免两套实现漂移。
- 代价是 `evaluation/` 从"离线工具"变成了"运行时依赖"，其代码质量要求随之提高。

### 5.2 JSON 字段结构

#### 5.2.1 `reports.dimensions_json`

```json
{"pronunciation": 70, "fluency": 78, "grammar_vocab": 74, "task_completion": 82}
```

四个键固定，前端 `Report.vue` 按固定顺序渲染进度条，缺键则该项不显示。

#### 5.2.2 `reports.fixes_json`

```json
[
  {
    "original": "I am very interest in this job.",
    "better": "I'm very interested in this role.",
    "reason": "interest 是名词/动词；这里需要形容词 interested，搭配 in。"
  }
]
```

#### 5.2.3 `reports.features_json`

来源两段，键集合如下（实测输出）：

| 键 | 来源 | 含义 | 示例 |
|---|---|---|---|
| `word_count` | 文本 | 总词数 | 25 |
| `filler_count` | 文本 | 填充词个数 | 0 |
| `filler_rate` | 文本 | 填充词/总词数 | 0.0 |
| `ttr` | 文本 | 类符形符比 | 0.84 |
| `mtld` | 文本 | MTLD 近似值 | 43.75 |
| `sentence_count` | 文本 | 句数（按 `.!?` 切分） | 2 |
| `mean_sentence_len` | 文本 | 平均句长 | 12.5 |
| `audio_duration_sec` | 音频 | 累计录音时长（秒） | 7.3 |
| `speech_rate_wpm` | 音频 | 语速（词/分钟，按总时长） | 205.48 |
| `articulation_rate_wpm` | 音频 | 发音速度（按有声时间） | 241.94 |
| `pause_count` | 音频 | 停顿次数（≥0.15s） | 3 |
| `mean_pause_sec` | 音频 | 平均停顿时长 | 0.243 |
| `pause_ratio` | 音频 | 停顿总时长/总时长 | 0.1 |

注意：

- 无音频时（如手动输入），只有文本类键 + `pause_count: 0`、`mean_pause_sec: 0.0`。
- 无用户发言时，仅 `{word_count: 0, pause_count: 0, mean_pause_sec: 0.0}`。
- `fluency_features` 本身也支持 `duration_sec`/`speech_rate_wpm`/`pause_count`/`mean_pause_sec`/`articulation_rate_wpm`/`pause_ratio`（当传入词级时间戳时），但后端**没有**传时间戳，故这些键实际由 `speech_features` 提供。同名键会被后者覆盖。
- 这些是**客观测量值**，不参与大模型打分，仅在报告页展示，供用户与评委交叉印证。

#### 5.2.4 `turns.audio_json`

```json
{"duration_sec": 3.2, "speech_time_sec": 2.8, "pauses": [0.2, 0.32]}
```

由前端 `audio.js` 在录音结束瞬间计算并随 `turn` 请求上报；无录音时为 `"{}"`。

### 5.3 数据约定

- **时间**：全部用 `datetime.utcnow` 写入**无时区 UTC**；序列化用 `isoformat()`，因此 JSON 里形如 `2026-10-29T02:23:04.779521`，**不带 `Z` 或偏移**。前端 `History.vue` 直接展示该字符串，导致界面上显示的是 UTC 时间（比北京时间早 8 小时的历史日期）。管理台用 `new Date(...).toLocaleString()` 做了本地化，表现正确。修复时不要给字符串补 `Z` 之后再让 `new Date` 解析——两个页面的处理方式需统一。
- **删除**：仅 `sessions → turns`、`sessions → report` 配了级联删除；删除用户不会级联删会话（当前无删除接口，暂无影响）。
- **枚举**：`role`、`status`、`difficulty` 均为普通字符串，靠代码约定而非数据库约束。
- **字符串存储的 JSON**：四个 `*_json` 字段都用 TEXT 存 JSON 字符串，读写处统一 `json.dumps(..., ensure_ascii=False)` / `json.loads(... or 默认值)`。这样在 SQLite 里可直接用 `sqlite3` 检查，代价是无法用数据库 JSON 函数索引。

## 6. API 规格

### 6.1 通用约定

| 项 | 约定 |
|---|---|
| Base URL（开发） | `http://127.0.0.1:8000` |
| Base URL（前端视角） | `/api`，经 Vite 代理转发 |
| 请求体 | `application/json; charset=utf-8` |
| 用户鉴权 | `Authorization: Bearer <JWT>` |

守卫逻辑（`router/index.js:28-41`）：

```js
const isPublic = to.path === '/login' || to.path === '/welcome'
// 没登录不要直接怼到登录页：先让新来的人看一遍欢迎页
if (!isPublic && !auth.token) return '/welcome'
if (to.path === '/login' && auth.token) return '/'
// 每个账号只看一次；旧版全局标记 '1' 没有用户名，当「未知」放行一次
if (to.path === '/welcome' && auth.token && to.query.again !== '1') {
  const mark = localStorage.getItem('sp_welcomed') || ''
  if (!!mark && mark !== '1' && mark === (auth.user?.username || '')) return '/'
}
```

**首屏顺序（v2 已改，别再按旧稿理解）**：双击 `start-all.bat` → 未登录 → **先看到欢迎页**（介绍这是什么、三步怎么用）→ 点「开始使用（先注册或登录）」→ 登录/注册 → 首页练习。
欢迎页按钮在已登录时变成「开始第一次练习」。若还是直接进登录页，是 Vite 缓存了旧模块，`Ctrl+F5` 或重开前端窗口。

- 点欢迎页按钮后，**本次浏览**不再弹第二遍：`sessionStorage.sp_intro_seen`（`Welcome.vue:34` → `Login.vue:88-97`），关浏览器失效。
- `localStorage.sp_welcomed` 存**看过引导的用户名**；等于当前用户名时再访问 `/welcome` 会被弹回首页，`?again=1` 一律放行。
- 旧标记 `'1'` 当「未知」处理，老账号也能补看一遍——这是之前「老账号永远看不到引导」的修复。

守卫只判断"有没有 token"，不校验是否过期；过期 token 会让首屏请求失败，由 axios 拦截器统一踢回登录页（并按原因给文案）。

### 7.6 语音链路

三条独立链路，全部依赖浏览器 API，**无后端音频处理**：

**① 语音识别 → 文本**（`utils/speech.js`）

```js
rec.lang = 'en-US'
rec.interimResults = true   // 边说边显示（灰色气泡）
rec.continuous = false      // 停顿即结束
```

- 仅 `window.SpeechRecognition || window.webkitSpeechRecognition` 存在时可用；不支持时前端提示"请用 Chrome，或点手动输入"。
- `onresult` 把 `event.results` 全部拼成一个字符串，相当于**只保留最终/最新转写**。
- Chrome 的 Web Speech API 实际使用云端识别，**需要联网**；网络受限时会出现识别错误或长时间无结果。

**② 朗读**（`utils/speech.js` + 可选后端 TTS）

```js
utter.lang = 'en-US'; utter.rate = rate   // 页面「慢 / 正常 / 快」= 0.85 / 1.0 / 1.15
window.speechSynthesis.cancel()            // 新语音打断旧语音
```

- 默认走浏览器 `speechSynthesis`，不需要任何 key。每条 AI 消息旁有 🔊 按钮可重听。
- 设置页可填**可选的语音合成密钥**（`X-TTS-Key / X-TTS-Base-URL / X-TTS-Model / X-TTS-Voice`，只存浏览器）。
  前端先试 `POST /api/tts`，**任何失败（含未配置）都回落 `speechSynthesis`**——TTS 挂了不能连朗读一起没。
- 错误码：`409 tts_not_configured` / `502 tts_key_invalid` / `502 tts_unavailable`；`TTS_API_KEY` 只是 `.env` 兜底。
- 兼容 OpenAI 兼容的 `/audio/speech`；讯飞/火山那种 AppID+Secret 三件套不在本契约内。

**③ 录音包络 → 语速/停顿**（`utils/audio.js`）

- `getUserMedia({audio:true})` + `AudioContext` + `AnalyserNode`（`fftSize=1024`）。
- 每 50ms 采样一次时域数据，算 RMS；**RMS > 0.02 视为有声**。
- 有声段累计为 `speech_time`；从有声转无声记为静音起点，下一次转有声时若静音时长 ≥ 0.15s 则记入 `pauses`。
- `stop()` 返回 `{duration_sec, speech_time_sec, pauses}`，全部保留 2 位小数。
- 麦克风权限被拒时 `startAudioCapture` 抛错，`Practice.vue` 捕获后置 `capturer = null`，**对话仍可继续**（只是没有音频特征）。这是有意的降级设计。

> 阈值 0.02 与 0.15s 是硬编码常量，在不同麦克风/噪声环境下表现差异较大，属于后续可配置项。

## 8. 评估与验证子系统

### 8.1 目标

回答两个问题：

1. **信度**：不同人评之间是否一致？（`ICC(2,1)`、`ICC(2,k)`、Pearson/Spearman、Cohen/Fleiss kappa）
2. **效度**：系统分与人评是否对得上？（Pearson/Spearman、MAE/RMSE、Bland-Altman）

### 8.2 模块

| 文件 | 行数 | 职责 |
|---|---|---|
| `agreement.py` | 183 | 全部统计量 + 解释区间 |
| `features.py` | 115 | 文本/音频特征提取（运行时也被后端复用） |
| `validate.py` | 118 | CSV 读取 → 计算 → JSON 输出 |
| `make_demo.py` | 60 | 生成合成演示数据（`seed=42`，20 条） |
| `demo_data.csv` | — | 合成数据，7 列 |
| `demo_report.json` | — | 一次运行的输出样本 |

### 8.3 统计量实现要点

| 函数 | 实现 | 备注 |
|---|---|---|
| `pearson(x, y)` | 标准协方差公式 | `n<2` 或方差为 0 → `nan` |
| `spearman(x, y)` | 先 `_ranks` 再 Pearson | `_ranks` 处理并列（取平均秩），实现正确 |
| `mae` / `rmse` | 绝对误差均值 / 均方根 | 需等长输入 |
| `bland_altman(a, b)` | `diff = a - b`，均值差 ± 1.96×SD | 返回 `n/mean_diff/sd_diff/loa_lower/loa_upper/within_loa/within_loa_ratio` |
| `cohens_kappa(r1, r2)` | `(po - pe) / (1 - pe)` | `pe >= 1` 时返回 1.0 |
| `fleiss_kappa(ratings)` | 行=样本、列=评分者 | 支持 2 人以上；每行人数必须一致 |
| `_icc(matrix, average)` | 双向 ANOVA，手算 `SS_rows/SS_cols/SS_err` | `average=False` → ICC(2,1) 绝对一致性；`average=True` → ICC(2,k) |
| `interpret_icc` / `interpret_kappa` | 区间映射为中文等级 | `nan` → "无法计算" |

ICC(2,1) 分母：`MSR + (k-1)MSE + k(MSC - MSE)/n`；ICC(2,k) 分母：`MSR + (MSC - MSE)/n`。与 Shrout & Fleiss (1979) 的两向随机、绝对一致性模型一致。

解释区间采用文献常见口径：ICC 用 Koo & Li (2016)，kappa 用 Landis & Koch (1977)。**这些区间是领域惯例，不是硬性阈值**，报告中应同时给出原始数值。

### 8.4 特征提取口径

`features.py` 只依赖标准库：

```python
FILLERS = {"um","uh","erm","hmm","mm","ah","like","well","actually","basically"}
_TOKEN_RE = re.compile(r"[A-Za-z']+")
```

- **分词**：只保留英文字母与撇号，小写化。中文、数字、标点被丢弃——这对英语口语场景是合理的，但意味着**中文夹杂内容不计入词数**。
- **填空词**：上表固定集合。`like`/`well` 在句中作实义词时也会被误计，属已知误差。
- **TTR**：`len(set(tokens)) / n`。
- **MTLD**：近似实现。以 `threshold=0.72`、`min_tokens=10` 累积，TTR 跌破阈值即计一个 factor 并重置；正反两遍取平均，最后 `n / factors`。与标准 MTLD 完全一致的前向/后向顺序细节略有差异，宜标注"近似"。
- **句数**：按 `[.!?]+` 切分后去空白。
- **`fluency_features(transcript, word_timings=None, pause_threshold=0.3)`**：`word_timings` 可选。传入时额外产出 `duration_sec`、`speech_rate_wpm`、`pause_count`、`mean_pause_sec`、`articulation_rate_wpm`、`pause_ratio`。
- **`speech_features(turn_word_counts, audio_metas, pause_min=0.15)`**：把每轮录音元信息求和后折算。语速按"总词数 / 总时长"，发音速度按"总词数 / 有声时长"，停顿占比按"停顿总时长 / 总时长"。

> 口径一致性：线上报告与离线验证共用同一份 `features.py`，这是刻意的设计（见 4.8）。但两处实现共享同一个近似 MTDL，误差也会被同时继承——写论文/答辩时应说明这是"轻量可解释指标"，不是 Praat 级别的声学分析。

### 8.5 CLI 用法

```powershell
# 1) 生成合成演示数据（覆盖 demo_data.csv）
python -m evaluation.make_demo

# 2) 计算一致性
python -m evaluation.validate --csv evaluation/demo_data.csv `
    --raters human1,human2 --system system `
    --bands human1_band,human2_band `
    --out evaluation/demo_report.json
```

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `--csv` | 是 | 使用 `utf-8-sig` 读取（兼容 Excel 导出的 BOM） |
| `--raters` | 是 | 人评分列名，逗号分隔 |
| `--system` | 否 | 系统分列名；给了才算效度指标 |
| `--bands` | 否 | 类别列；≥2 列才算 kappa |
| `--out` | 否 | 额外写一份 JSON |

- 有效样本 `n < 3`：只返回 `{n, raters, warning}`，不算指标。
- 系统分比较要求 `n >= 3` 才输出 `system_vs_human_mean`。
- 档位 kappa 要求至少 2 条完整档位样本。
- ⚠️ 注意：ICC 与相关性使用**过滤后**的样本（人评分必须齐全），而 kappa 用的是**原始行**中档位齐全的子集。当两类缺失模式不同时，两部分的 `n` 可能不一致，报告里应各自注明样本数。

### 8.6 数据采集规范

来自 `docs/validation.md`，此处补充实现视角的约束：

1. 2–3 名英语教师**独立**打分，互不可见。
2. 对系统分**盲评**（不告诉老师系统给了多少）。
3. 使用同一份 rubric（对齐 CEFR / IELTS 描述语）。
4. 每样本至少两人评，**建议 ≥ 20 条**（演示数据正好 20 条）。
5. 保留原始录音与转写，保证可复现。

**诚实声明**：`demo_data.csv` 是合成数据；真实结论必须来自真人评分。答辩时若被追问"这个 ICC 是真的吗"，正确答案是"脚本可信、数值是合成的，真实数据正在采集"。

## 9. 评分体系设计

> 完整的量表、锚点与校准记录见 [rubric-band.md](rubric-band.md)；本节只讲**怎么算**，数值口径以代码为准。

### 9.1 维度集合随作答方式变化

| 维度 | 键 | 出现条件 | 证据来源 |
|---|---|---|---|
| 发音清晰度 | `pronunciation` | 有录音轮 | 仅模型按转写推断（本项目不做声学测评） |
| 流利度 | `fluency` | 有录音轮 | 模型 + 规则分（语速/停顿/填充词） |
| 语法词汇 | `grammar_vocab` | 恒有 | 模型 + 规则分（复杂度） |
| 任务完成度 | `task_completion` | 恒有 | 模型 + 规则分（场景清单命中） |
| 文字表达 | `written_expression` | 有打字轮 | 仅模型（书面组织与用词） |

纯打字 3 维、纯录音 4 维、混合 5 维。**后端会把模型多给的维度丢掉**：打字轮不进发音/流利度，录音轮不进文字表达（`rules.py:343-347`）。
混合会话里填充词只从录音轮统计（纯打字的 `features` 里干脆没有 `filler_rate` 等字段）。

### 9.2 综合分：按模式加权，不是模型直给

| 作答模式 | pronunciation | fluency | written_expression | grammar_vocab | task_completion |
|---|---|---|---|---|---|
| `voice` | 20 | 20 | — | 30 | 30 |
| `typed` | — | — | 35 | 35 | 30 |
| `mixed` | 15 | 15 | 20 | 25 | 25 |

权重在 `evaluation/bands.py:33-52`（`DIMENSION_WEIGHTS`），由 `rules.py:414-415` 调用；缺失维度按剩余权重重新归一，不当 0 分；认不出模式才退回等权平均。
综合分与 band 由代码算出并落库，**不再是模型给一个 `total` 就存**——旧稿那句「总分由模型直接给出、与四维可能不自洽」已作废。

### 9.3 模型分与规则分怎么融合

1. **模型先给 band**：每个维度按雅思描述语给 0.5 步长的 band，再 `S = 10B + 10` 换 0–100（全项目唯一换算入口 `evaluation/bands.py`）。
2. **规则分**（可复现，纯标准库）：
   - 流利度 = `0.40·f_wpm + 0.35·f_pause + 0.25·f_filler`，映射到 45–90；没有录音则无规则分（不拿填充词硬凑）。
   - 语言复杂度 = `0.45·f_mtld + 0.35·f_msl + 0.20·f_cx`；无标点且无停顿估计时，句长项的 0.35 权重让给从句标记。
   - 任务完成 = `40 + 60 × 场景清单命中率`。
3. **单维融合权重**（规则:模型）：发音 0:1、流利度 0.5:0.5、语法 0.35:0.65、任务 0.6:0.4、文字表达 0:1。
4. **只压不抬**：模型比规则分高 **>20 分**时压回 `rule + 10`（`CLAMP_GAP / CLAMP_TO`）；规则分显著高于模型（>20）不抬分，只在报告里标「请人工复核」。
5. **可复现**：每维的 `model_score / rule_score / final_score / clamped / clamp_reason` 和参与计算的输入一起写进 `reports.scoring_json`，
   接口出参字段名是 `scoring_detail`（注意这两个名字不同，查库/查响应别搞混）。

### 9.4 档位、跨模式可比与降级

- **取整**：`B = (S−10)/10`，`floor(B×2+0.5)/2`；`S < 40` 不给 band（显示「低于 A2」）；CEFR 按 B1=4.0–5.0、B2=5.5–6.5、C1=7.0–8.0 归段。
- **两个 band 别混**：报告页的 `band` 是本模式加权分的档位，历史/成长曲线的 `comparable_band` 只取两种作答都评的两个共享维度（语法词汇 + 任务完成），用于跨模式比较。
  同一场混合会话，两个值差 0.5 是正常的，不是自相矛盾——报告页应标明是本模式口径。
- **降级**：模型不可用时 `source=mock`，`total_score / band / cefr` 全为 `null`，`mock_reason` 取 `invalid_key`（服务端兜底密钥失效）/ `unavailable`（超时、不可达、解析失败）/ `not_configured`（中途丢 key）。
  报告标「示例报告（模型不可用）· 本次不计分」，`sentence_fixes` 只列用户真实说过的句子，不写死任何示例句。
- **改写硬校验**：模型给的 `original` 必须能在该用户转写里找到（忽略大小写与标点），找不到直接丢弃——防模型编句子。
- **约束**：输出纯 JSON、`temperature=0.2`、`sentence_fixes` 1–3 条；中文写 `comment` / `reason`，英文保留 `original` / `better`。

### 9.5 可测指标与分数的关系（与旧稿的区别）

旧稿写的是「语速/停顿/TTR/MTLD 只展示、不参与打分」。**现在它们参与规则分并与模型分融合**（见 9.3），所以：
报告页的「评分依据（可复现）」能当场把某一维的规则分、模型原分、压分原因摊开算——这是评审最容易追问、也最容易验证的一块。
仍然不声称的是：没有声学/音素级测评，发音维只有文本推断；规则权重在**真实人工标注数据上尚未校准**，`evaluation/demo_data.csv` 是合成数据，只证明脚本通路。

## 10. 运行与部署

### 10.1 环境要求（实测）

| 组件 | 版本 | 来源 |
|---|---|---|
| Python | 3.14.4 | `backend/.venv` 基于系统 Python 创建 |
| fastapi | 0.162.0 | `.venv` 已安装 |
| sqlalchemy | 2.1.6 | 同上 |
| PyJWT / httpx / python-dotenv / uvicorn | 见 `requirements.txt` | 同上 |
| Node.js | v24.22.1 / npm 11.19.1（本机位于工作区 `.tools\node-v24.22.1-win-x64`，脚本会自动查找） | 见 TD-02 |
| 浏览器 | Chrome（语音识别） | — |

`requirements.txt` 全部为 `>=` 下限，无锁文件，因此**不同机器装出的版本可能不同**。若要严格复现，建议补 `pip freeze` 或 `uv.lock`。

### 10.2 首次安装

`setup.ps1` 做三件事：

1. 找 Python：优先 `D:\python\python.exe`，否则用 PATH 上的 `python`；创建 `backend/.venv`（`--without-pip`），再 `ensurepip`，然后装 `requirements.txt`。
2. 把 `TEMP`/`TMP` 指向仓库内 `.tmp/`，规避系统临时目录权限问题。
3. 解析 Node 目录（`tools\node` → `..\.tools\node-*` → 系统 PATH），前置到 `PATH`，然后在 `frontend/` 执行 `npm install`。

### 10.3 启动

**推荐：双击 `start-all.bat`**

1. 开一个 `cmd` 窗口跑 `start-backend.bat`（期间 2s）。
2. 开第二个窗口跑 `start-frontend.bat`（期间 8s）。
3. 打开 `http://127.0.0.1:5173`。

`start-backend.bat` 额外做了**端口清理**：`netstat` 找 `127.0.0.1:8000` 的 LISTENING 进程并 `taskkill /F`，2s 后复查，仍被占用则提示并 `exit /b 1`。这对反复演示很实用——避免"端口被上次的进程占着"导致启动失败。

手动启动：

```powershell
.\start-backend.ps1    # 需先有 backend\.venv，否则提示运行 setup.ps1
.\start-frontend.ps1   # 自动解析 Node 目录后 npm run dev
```

后端启动成功的标志：`Uvicorn running on http://127.0.0.1:8000`。

### 10.4 生产部署现状与建议

**现状**：只有开发形态。`frontend/dist/` 虽已构建，但**后端不托管该产物**，`vite preview` 也不在启动脚本中。因此：

- `dist` 里的 `index.html` 引用的是 `/assets/...` 绝对路径，若直接交给静态服务器托管，`/api` 无人代理会全部 404。
- 目前"部署"等同于"在演示机上跑两个 dev 进程"。

**建议的最小方案**（三选一）：

1. **Nginx 反代**：静态托管 `dist/`，`location /api { proxy_pass http://127.0.0.1:8000; }`。
2. **后端托管静态**：在 `main.py` 里 `app.mount("/", StaticFiles(directory="../frontend/dist", html=True))`，但需把它放在所有 `/api` 路由注册**之后**，否则会吞掉 API 路由。
3. **Docker Compose**：两个服务 + 一个 Nginx。

无论哪种，都需要处理 SPA 的 history 路由回退（未匹配路径返回 `index.html`），否则 `/report/1` 直接刷新会 404。

### 10.5 端口与文件权限

| 项 | 值 |
|---|---|
| 后端监听 | `127.0.0.1:8000`（仅本机，非 `0.0.0.0`） |
| 前端监听 | `127.0.0.1:5173`（仅本机） |
| 数据库文件 | `backend/speakpal.db` |
| 静态资源 | `backend/app/static/` |
| 临时目录 | 仓库根 `.tmp/`（`setup.ps1` 会设置） |

只监听回环地址意味着**局域网其他设备无法访问**，答辩若需投屏演示需改为 `--host 0.0.0.0`（并注意这会把无鉴权强度的管理台暴露出去）。

| P1 | 采集 20–30 条真人评分数据，产出真实 `agreement` 报告 | 让"可验证"从工程自测升级为真实结论——这是本题的核心加分点 |
| P1 | 把语速/停顿特征纳入评分（规则分 + 大模型分加权），并说明权重 | 让客观指标真正参与诊断，而非仅展示 |

## 附录 D：v1.0 → v2.0 主要变更

v1.0 写于 2026-10-29 上午，之后代码又走了 band、打字分流、练习增强、账号安全四大块。以下是本文档这一版按代码改掉的内容，
旧结论不要再用（评审若看过旧稿，这里能对上差异）：

| 主题 | v1.0 的说法 | v2.0（当前代码） |
|---|---|---|
| 评分产物 | 模型直接给 `total_score`，四维只是展示 | 模型给每维 band → 规则分融合（只压不抬）→ 按作答模式加权算综合分，明细落 `scoring_json` |
| 维度数 | 固定四维 | 3/4/5 维，随作答方式变；打字轮不计发音/流利度，录音轮不计文字表达 |
| 客观指标 | 语速/停顿/MTLD 只展示、不参与打分 | 它们是规则分的输入，与模型分融合 |
| 降级 | mock 报告含写死的示例纠错句 | 降级不计分（分数/档位为 `null`），`original` 必须来自用户转写，`mock_reason` 落库 |
| 接口规模 | 14 路径 / 15 操作 | 30 个 `/api` 操作（见 §6.2），新增练习增强、配置与数据管理、管理员用户管理 |
| 时间格式 | ISO 8601 无时区 | 出口统一带 `Z` 的 UTC，前端按本地时区显示 |
| 鉴权 | 只讲 JWT | 加 `token_version`：改密码即让其他设备掉线 |
| 密钥 | 只有 `backend/.env` 一把 | 用户 key 存浏览器、随请求头发送，`.env` 仅兜底；无 key 开练 409、key 被拒 502 |
| 文档关系 | 本文取代 design.md | 两份并存，`design.md` 是口径来源 |

**仍然成立、没有变的部分**：单一换算锚 `S = 10B + 10`、CEFR/雅思对照、`evaluation/` 的一致性验证方法、
"合成数据只证明通路"这条诚实声明、以及发音维度不做声学测评的边界。
